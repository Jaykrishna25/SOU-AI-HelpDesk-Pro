How the roles connect

Seven roles, one capability matrix. Nothing below is enforced by asking nicely — every gate is a check in lib/policy.ts, and for the AI features it is enforced by which tools get bound to the agent rather than by wording in a prompt.

The hierarchy, and what each rank adds

Separation of duties — nobody approves their own work

The grievance path — handled by one role, identified by another

Where the AI is gated — by binding, not by instruction

This is the difference worth defending. Most systems tell the model what not to do — “never reveal institutional figures to a student.” That is a request, and requests can be argued with. Here the function is never passed in, so there is no phrasing that reaches it. The question stops being “will the model comply?” and becomes “was the function bound?”

What happens when something is unknown

An unrecognised role
Treated as STUDENT. A typo in a role string fails closed, never open. Tested.
A token with no version claim
Rejected. This was a real finding — the check previously skipped such tokens entirely.
Retrieval below the confidence floor
OakMitra says it does not know and offers a ticket. It does not improvise.
A question about your own record
Refused before retrieval runs at all, and routed to a person.
A figure no tool produced
Not stated. The fee assistant gives the overdue amount and declines to invent the penalty rate.
An evidence gap in a report
Listed as a gap. Nothing is filled in, and no accreditation outcome is predicted.
